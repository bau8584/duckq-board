# PLAN — 1단계: 실제 앱 (DuckQ Board)

> 2026-09-29 시작(메모만). **코드는 hq 판정(웹으로 간다) 뒤에 시작.** 기능 목록 원본은 `SPEC-observed.md`.

## 1. 0단계에서 확인된 전제
- **메모리는 넉넉함.** 소리 데이터 = 효과음(통째로 풀어 둠) + 긴 곡 D(곡당 최대 1.8MB, 122분 mp3·224MB wav도 같음). 극단 실제 판(효과음 20 × 5초 + 긴 곡 3 동시)으로 잡아도 **50MB 안팎** — 경고선 300MB의 1/6, T5에선 900MB까지 안 튕김(iPad Pro 11"). 브라우저 자체 사용량은 빠진 숫자.
- 긴 곡은 **D(직접 풀기)**, `<audio>`는 D 곡에 만들지 않는다(옆에 있기만 해도 소리가 튐).

## 2. 0단계에서 나온, 앱에 그대로 넣을 것
| 무엇 | 근거 |
|---|---|
| 다시 열면 **이어서 틀지 않음**(판·파일만 복원) | 소유자 결정 2026-09-29 |
| 홈 복귀 때 소리 출구(AudioContext)가 죽었으면 **첫 탭에서 새로 만들기**, 멈춰 있던 곡은 멈춤 표시, 뒤에서 계속 흐른 곡은 그대로 | T8 (0.4.7) |
| 새로 연 페이지가 **옛 페이지 소리를 끄기**(한 번에 하나만) | T9 — 밀어 끈 페이지가 살아남아 재생 |
| 곡별 **페이드인/아웃 설정**(0.5~2초) | 시작 지직 = 페이드인 없이 갑자기 시작(소유자 의견) |

## 3. 기능 후보 (남는 메모리 쓰기) — 미결정
| 후보 | 내용 | 사용자가 느끼는 것 | 메모리 |
|---|---|---|---|
| **A. 통째로 올리는 기준 30초 → 2~3분** (Claude 추천) | 짧은 곡을 조각이 아니라 통째로 풀어 둠 | 배경 반복음(빗소리·군중) **이음새 완벽**, 되감기·구간 반복 즉시. 앱이 길이 보고 알아서 고름(관리자 할 일 0) | 3분 곡 ≈ 66MB |
| B. 다음 판 미리 올려 두기 | 판이 여럿일 때 옆 판 효과음 미리 풀기 | 판 넘기자마자 첫 소리 즉시 | 판당 ~40MB |
| C. 긴 곡 첫 1초 미리 풀기 | 모든 긴 곡 앞부분 준비 | 0.05초 → 더 짧게, **체감 거의 없음** → 뒤로 | 곡당 0.4MB |
