## 3. 소유자 선택의 경향 (다음에 먼저 적용할 것)

1. **대상이 보여야 한다.** "무엇을 / 어디에 / 몇 개" 가 늘 화면에 있어야 안심한다. → 새 창·새 일괄 기능엔 **대상 표시부터** 설계.
2. **말보다 모양.** 숫자·단추 나열을 싫어하고, 익숙한 도구(프리미어, 사운드보드, 아이폰 홈 화면)의 **형상**을 가져오길 원한다. → 조절은 "끄는 막대·비탈·손잡이"를 먼저 떠올린다.
3. **짧은 이름 + 숨긴 설명.** 글이 늘 보이는 걸 싫어한다. 이름은 2~6글자, 설명은 [?]. → 문구를 쓸 때 "설명 없이도 알아먹나"로 먼저 거른다.
4. **위계와 일관성에 민감.** 같은 급인데 다르게 생기거나(인/아웃 줄), 다른 급인데 같이 생기면(보드 vs 모든 보드) 바로 짚는다. → 같은 개념 = 같은 모양·같은 기호(↺, ◣, 테두리).
5. **예외 없는 규칙.** "색 없는 건 보드 색으로" 같은 특례를 "규칙이 없어 보인다"고 싫어한다. → 특례를 만들면 이름을 붙여 일반 규칙으로 편입(→ "투명").
6. **화려함보다 조용한 확실함.** 효과를 더하다가 "화려하다"로 한 번에 덜어 낸다. → 신호는 **하나를 세게**, 여럿을 약하게 겹치지 않는다.
7. **흔들리지 않는 화면.** 칸 길이가 상태에 따라 바뀌는 것을 즉시 잡는다. → 새 칸은 **높이 고정**부터.
8. **되돌릴 수 있으면 과감하게.** 위험한 일괄 기능도 되돌리기가 있으면 받아들인다. 확인창보다 되돌리기를 선호.
9. **실사용 앱을 기준으로 삼는다.** 사운드보드(30초 페이드, 테두리)를 보고 요구가 나온다. → 판단할 때 "사운드보드는 어떻게 하나"를 먼저 확인.
10. **판단을 먼저 묻고, 시험 뒤 기각 권한을 남긴다.** "판단만", "해 보자, 다만 기각할 수 있음". → 확신 없는 효과는 **[시험 중] 표시 + 뺄 자리**를 만들어 넣는다.
