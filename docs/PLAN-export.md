# PLAN — 판 내보내기·가져오기 (2026-09-29, 0.3.40 PC 시험 통과 · 아이패드 시험 남음)

## 정한 것 (2026-09-29 소유자)
1. zip(압축 없이 담기, **원본 형식 그대로**, 이름만 패드 이름) + board.json. 라이브러리 대신 app/zip.js 직접(오프라인 안전).
2. 범위 = 보드 하나(보드 설정 → 파일 [내보내기][가져오기]).
3. 가져오기 = 늘 새 보드로 더하기.
4. 저장 = 다 만든 뒤 알림의 [저장] → 공유 창, 안 되면 다운로드(로그에 어느 쪽인지 남음).
5. 300MB 넘으면 경고.
6. (0.3.42) 트림한 긴 곡은 **앞뒤 3분 남기고 잘라 담기** — 변환 없이 조각 단위(wav 샘플·mp3 프레임·m4a 샘플+목차 새로 쓰기), app/cut.js. 트림 위치는 자동 보정. PC 시험: 세 형식 어긋남 0~1ms, 20분 곡 → 약 1/3.

## 버린 방법 (추가)
| 방법 | 이유 |
|---|---|
| PC에서 잘라 넣기 안내 | 관리자에게 PC 요구 — 기기 안에서 해결해야(소유자) |
| 전부 m4a로 변환 | 120분 풀면 약 2.5GB → 아이패드 메모리 초과, 음질 손실, mp3→m4a는 크기 거의 같음 |

## 남은 것 — 아이패드 시험(로그로 판정)
- [ ] 내보내기 → [저장] → 공유 창 뜸(로그 "공유 창 완료"/"다운로드로") → 파일 앱에서 패드 이름으로 보임
- [ ] 가져오기 → 새 보드, 소리 다 재생, 기존 보드 그대로
- [ ] 비행기 모드에서 위 둘
- [ ] 긴 곡 많은 보드(수백 MB)에서 걸린 초·실패 여부 · 로그 "잘라 담음 A→B MB"
- [ ] 잘라 담은 곡을 가져와 트림 시작이 원래와 같게 들리는지(사파리 mp3 지연 처리 확인)

## 왜
- 소유자 요청: 패드 이름을 바꾸면 원본 파일 이름도 바꾸고 싶다 → 웹앱은 아이패드 원본(파일 앱)에 손댈 수 없음(브라우저 보안). 앱엔 **복사본**만 있고 그 이름은 패드 설정 정보 줄에만 보임.
- 그래서 원래 원한 효과 = **내보낼 때 파일 이름을 패드 이름으로**. 겸해서 백업·다른 아이패드로 옮기기·극단 동료에게 판 넘기기.

## 지금 구조 (근거)
- 소리 파일: IndexedDB `duckq-board` (store.js) — `{id,name,size,type,blob}`. 판·설정: localStorage `duckq-board-v1` (S = boards·pads·settings·master).
- 오프라인 저장(sw.js)으로 앱은 인터넷 없이 켜짐 → **외부 라이브러리를 CDN에서 받으면 오프라인에서 깨짐.** 쓰려면 app/에 넣고 index.html에 ?v=로 걸어 SW가 같이 담게.
- 공개 주소 bau8584.github.io/duckq-board/app/ (main), 소유자는 q.deokgu.com/app/ (PC 폴더 = dev).

## 정할 것 (새 세션 첫 답에서 후보+추천)
1. **담는 방식**: ① zip(안에 `패드이름.mp3`들 + 판 설정 json — 파일 앱에서 열면 소리가 보임, 라이브러리 필요) ② 앱 전용 한 파일 `.duckq`(라이브러리 없음, 밖에선 못 엶).
2. **범위**: 전체 / 보드 하나 / 고른 패드(편집 막대에 [내보내기]).
3. **가져올 때**: 새 보드로 더하기(안전) / 판 통째로 바꾸기(되돌리기 필요).
4. **아이패드에서 저장**: 공유 시트(`navigator.share` files) vs 다운로드 링크 — 둘 다 시험.
5. **용량**: 수백 MB면 메모리. 긴 곡 많을 때 아이패드에서 실제로 되는지 시험 필수.
