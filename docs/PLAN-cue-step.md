# PLAN — 번갈아 큐 (2026-10-01) ✖ 만들어 봤다가 버림

## 왜
실사용 로그(2026-10-01): 큐 5~10이 "접속"→"정제"→"접속"→"정제"… 6줄. 대사 주고받을 때마다 GO.
줄이 많고, 담다가 '끄기' 줄(7·8)을 넣었다 고치는 혼동도 있었음.

## 결정 (소유자)
- A안 채택: **한 줄에 트랙 1개 이상 + 횟수.** GO 누를 때마다 목록의 다음 트랙을 튼다. 다 돌면 다음 줄로.
  - 트랙 1개 = 같은 소리를 GO마다 다시(예: 노크 ×5). 패드 반복(저절로 돎)과 다름 — 이건 GO마다 한 번씩.
  - 트랙 2개 이상 = 번갈아(`접속 ↔ 정제 ×3`).
- 표시: 한 줄 + 진행 점(●●○○○○). 앞 트랙은 기존 "다른 소리 나오면 꺼짐"으로 저절로 꺼짐.

## 버린 방법
- B 묶어 보이기만: 담는 수고가 그대로.
- C 되돌이표 큐: 순서를 머리로 따라가야 함.

## 끝 기준(안)
1. 큐 한 줄에 트랙 2개·×3을 담으면 GO 6번에 번갈아 나오고 7번째 GO는 다음 줄.
2. 트랙 1개 ×5도 같은 식으로 동작.
3. 내보내기→가져오기 로그 `전부 같음` 두 줄(패드 id 목록이라 `Cue.exportFix/importFix` 손봐야 함).

## 확인할 것
- 진행 중 위치(몇 번째)를 줄 누름·장면 이동·전체정지 때 어떻게 되돌릴지.
- 기존 큐 데이터는 그대로(목록 없음 = 지금 동작).

## 결과 — 버림 (2026-10-01, 소유자)
- 0.3.78로 만들어 끝 기준 3개는 통과했으나 되돌림(배포 전).
- 이유: 큐 = "한 줄 = GO 한 번 = 한 순간". 한 줄이 GO 여러 번을 품으면 목록·큐시트만 보고 흐름을 못 읽고, 몇 번째인지 머리로 따라가야 함(C안 되돌이표와 같은 약점).
- 담는 수고는 기존 [편집 → 고르기 → 복제]로 푼다.
