## 1. 만들 것 — 검증 페이지 1장 (`test/engine.html`)

앱이 아니다. 버튼 몇 개와 로그 창뿐인 한 페이지. 배포는 GitHub Pages 또는 로컬 https(홈화면 설치엔 https 필요).

| 요소 | 내용 |
|---|---|
| 시작 버튼 | 첫 탭에서 AudioContext 생성·재개(자동재생 정책 해제) |
| 파일 넣기 | 여러 개 선택. 넣는 즉시 IndexedDB에 저장 + 분류(30초 이하 → 메모리 적재, 초과 → 스트리밍) |
| 격자 버튼 | 파일마다 하나. 탭=재생, 재생 중 탭=페이드아웃 2초 |
| 효과음 적재 총량 표시 | 디코딩된 바이트 합. **300MB 넘으면 경고** |
| 지연 측정 | 탭 시각 → 실제 소리 시작 시각(AudioContext.currentTime 기준) 차이를 ms로 로그 |
| 자동 연타 | GO 300회를 1초 간격으로 자동 실행(효과음 무작위) |
| 화면 꺼짐 방지 | Wake Lock API 켬. 상태 표시 |
| 상태 자동 저장 | 재생 중 목록·위치를 1초마다 저장. 다시 열면 복원 + "복귀 n초" 로그 |
| 로그 내보내기 | 텍스트로 복사 |

**엔진 구조(앱에 그대로 가져갈 것)**
- 효과음: `decodeAudioData` → AudioBuffer → `AudioBufferSourceNode` → GainNode(페이드) → 출력
- 긴 곡: `<audio>` 요소(src = IndexedDB Blob URL) → `MediaElementAudioSourceNode` → GainNode → 출력
- 끼어들기 감지: `AudioContext.onstatechange`(interrupted/suspended) → 자동 `resume()` + 로그
- 저장: 음원 Blob은 IndexedDB, 설정·상태는 localStorage

## 3. 테스트 항목과 합격 기준

| # | 테스트 | 방법 | 합격 |
|---|---|---|---|
| T1 | 효과음 지연 | 효과음 50회 탭, 지연 로그 | 평균 **20ms 이하**, 최대 50ms |
| T2 | 긴 곡 시작 지연 | 긴 곡 20회 | 평균 **100ms 이하** |

| T4 | 2시간 연속 | 긴 곡 반복 재생 상태로 자동 연타 300회 × 반복, 2시간 | 정지·튕김 0, 지연 증가 없음 |
| T5 | 메모리 압박 | 효과음 적재를 900MB까지 늘림 | 300MB 경고가 뜨고, 그 이하에선 튕김 0. (900MB에서 튕기는 건 정상 — 상한 근거) |
| T6 | 전원 버튼 | 재생 중 전원 버튼(잠금) 후 해제 | 자동잠금 "안 함"+접근 가이드에서 **잠기지 않음** 확인. 강제로 잠그면 끊기는 건 알려진 한계 → 복귀 시간만 기록 |
| T7 | 끼어들기 | 재생 중 FaceTime 수신·시리 호출·알람 | 끝난 뒤 **자동 복귀** 또는 한 탭 복귀. 복귀 5초 이내 |
| T8 | 앱 전환 | 홈으로 나갔다 30초 뒤 복귀 | 상태 복원 **3초 이내**(끊김 자체는 알려진 한계) |
| T9 | 강제 종료 | 앱 스와이프로 죽이고 다시 열기 | 파일 다시 안 넣어도 됨, 같은 판, 3초 이내 |
| T10 | 7일 보관 | 홈화면 앱 상태로 7일 방치 후 열기 | 음원 그대로 있음 |
| T11 | 블루투스 | 스피커 지연 체감·끊김 | 지금 Soundboard Studio와 **같은 수준**이면 합격(절대값 아님) |
| T12 | 무음 스위치·볼륨 | 무음 모드에서 재생 | 안 나면 점검표 항목으로 확정(합격/불합격 아님, 기록) |

**종합 판정**
- T1~T5·T9 전부 합격 → **웹으로 간다** (1단계 착수)
- T4 또는 T5(300MB 이하)에서 튕김 → 상한 낮추고 재시험, 그래도 안 되면 한계로 기록(앱 전환 없음)
- T7·T8 복귀가 10초 넘음 → 복귀 로직 보강 후 재시험

## 7. q.deokgu.com 연결 — 남은 일 (2026-09-28)

**이미 된 것**: 터널(Docker `C:\srv\local-backend`, 자동 재시작) · `q.deokgu.com` 연결 설정 · 문지기(로그인) · 엔진 페이지·로그 자동 전송 · 중계 Worker 초안(`worker/`, 미배포).
**빠진 것**: 로그 서버(`test/log-server.py`)가 Docker 밖 파이썬이라 **자동으로 안 켜짐** → 지금 꺼져 있음(로그인 뒤 오류 화면).

**정한 방법(소유자 선택 A)**: 로그 서버를 Docker 상자 `duckq`로 넣는다.
1. `docker-compose.yml`·`cloudflared/config.yml`을 `backup/`에 `.bak-20260928`로 복사
2. compose에 `duckq` 서비스 추가: `python:3.13-alpine@sha256:79e7a9b9ff1cbceff819f856fb374477792a5967759d94df266de7b7b4120e6f`(3.13.15), `restart: unless-stopped`, `command: python -u /app/test/log-server.py`, `TZ: Asia/Seoul`, 볼륨은 `duckq-board/test → /app/test:ro`, `duckq-board/logs → /app/logs` **두 개만**(영상·캡처 폴더가 주소로 안 보이게). tunnel의 depends_on에 duckq 추가, 맨 위 주석 "상자 5개"로
3. `config.yml`의 q 줄 `service: http://host.docker.internal:8765` → `http://duckq:8765`
4. `docker compose up -d` + `docker compose restart tunnel` (api·files가 몇 초 끊김) — **실행 중 서버 변경이라 자동 승인이 막음 → 소유자 승인 받고 실행**

**끝 기준**: ① 아이패드(집 와이파이도 됨 — 주소가 Cloudflare를 거치므로)로 `q.deokgu.com/test/engine.html` → 로그인 후 페이지 뜸 ② 버튼 누르면 `logs/engine-날짜.txt` 줄 늘어남 ③ PC 재시작해도 ①② 그대로.

**진행 (2026-09-28)**: 1~4 완료(4는 소유자가 터미널에서 실행). 상자 안에서 페이지 200·로그 쓰기 204로 ② 통과. ①③은 소유자 아이패드 확인 대기.

**버린 방법**: 윈도우 예약 작업으로 로그인 때 켜기(B) — 멈추면 안 살아나고 관리처가 둘로 나뉨. Worker 배포(PC 꺼짐 대비)는 PC 켜 두고 테스트하면 불필요 → 뒤로 미룸.
