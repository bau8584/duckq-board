> 2026-09-29 소유자 아이패드 첫 사용 후 논의. 세션 "[DuckQ] 웹제작: 1단계 뼈대 ②"에서 정함, 코드는 다음 세션.
> 앞 내용: `PLAN-stage1.md` §6. 화면 원본: `DESIGN.md`. 엔진: `app/engine.js`(0.4.7 구조).

## 끝 기준 (아이패드 화면으로)
1. 패드·보드 탭을 길게 누르면 설정이 열리고, 짧게 누르면 소리만 난다.
2. 페이드 설정 창에서 곡 전체의 페이드인/아웃을 보고 바로 바꿀 수 있고, 곡이 끝까지 가도 페이드아웃이 걸린다.
3. 일시정지·정지에서 지직 소리가 안 난다.

## 할 일 (결정됨)
| # | 할 일 | 정한 것 |
|---|---|---|
| 1 | 패드 이름 글자 | 한 단계 작게. 설정에 글자 크기 작게/보통/크게(기본 = 새 보통) |
| 2 | 길게 누르기 | 패드 0.5초 누르고 안 움직임 → 소리 대신 패드 설정. 보드 탭 길게 → 보드 설정. **잠금 중엔 안 열림** |
| 2 | 편집 버튼 = 여러 개 다루기 모드 | 흔들림·끌어 옮기기·정렬 유지 + 패드 눌러 **여러 개 선택** → 아래 단추: 복제·삭제·다른 보드로·**선택한 곡 일괄 수정**(색·볼륨·페이드·루프 등 같은 값으로) |
| 3 | 페이드아웃 하나로 | 같은 값이 **곡 끝에 닿을 때 + 다시 눌러 끌 때** 둘 다. 트림 구간 끝도 곡 끝으로 봄 |
| 3 | 기본값 | 페이드인·아웃 **모두 끔** (새로 넣는 곡) |
| 3 | 페이드 설정 창(새) | 보드 곡 전체 목록: 줄마다 페이드인/아웃 켬·초. 위에 [전체 켜기][전체 끄기][전체 N초로] + 새 곡 기본값 |
| 3 | 설정 이름 | "전체 페이드 시간" → "◣ 버튼 페이드 시간". "모든 패드에 이 시간 쓰기"는 페이드 창으로 대체 여부 판단 |
| 4 | PLAYED 저절로 지움 | **잠금 켤 때 지움 + 8초 [되돌리기]**, 그리고 **마지막 사용 6시간 뒤 자동**. 설정의 지우기 단추는 예비로만 |
| 5 | 지직 | ⏸: 30ms 줄인 뒤 멈춤 / 이어서: 30ms 올림. ⏸ 중 ■: 소리 막은 채 정리(출구를 다시 켤 때 새어 나가지 않게) |
| 6 | 트림 저장 | 트림만 [저장][취소]. 저장 안 하고 닫으면 묻기. 나머지 항목은 지금처럼 바로 적용 |
| 7 | 로그 자동 전송 | q.deokgu.com에서 열면 5초마다 PC로. **`logs/app-날짜.txt` 따로** — `test/log-server.py`에 경로 하나 추가(검증 창과 같이 쓰는 파일 → 검증이 쉴 때). 설정의 기록 보기·복사는 남김 |

## 진행 (2026-09-29, 세션 "[DuckQ] 웹제작: 피드백 1차")
- 1~6번 코딩 끝(앱 0.3). PC에서 길게 누르기·여러 개 고르기·일괄 수정·페이드 창·⏸/■ 동작 확인. **아이패드 귀·손 확인 전.**
- "모든 패드에 이 시간 쓰기"는 페이드 창 [전체 이 시간으로]로 대체. 켜 둔 사람에게만 설정에 남겨 끌 수 있게.
- 편집 모드에서 패드 하나 설정은 1개 골랐을 때 아래 막대 [설정] 또는 평소 길게 누르기.
- 7번 끝(0.3.1): 앱이 q.deokgu.com에서 열리면 5초마다 `/log-app` → `logs/app-날짜.txt`. PC 서버는 다시 켜야 적용. q.deokgu.com에 app/ 열기는 아직(소유자 승인).

## 확인 필요
- 화면 꺼짐 방지(Wake Lock)가 홈화면 앱에서 실제로 되는지: 자동 잠금 2분 두고 3분 켜 두기. 공연 안내는 자동 잠금 '안 함' + 접근 가이드.

## 버린 방법
| 방법 | 이유 |
|---|---|
| 곡 끝 페이드와 끌 때 페이드를 따로 | 소유자: 같은 설정이어야 함. 효과음 뭉개짐 걱정은 기본값 '끔'으로 해결 |
| 편집 버튼으로만 패드 설정 열기 | 손 뗄 때 재생으로 바뀌어 길게 누르기가 가능해짐 |
| PLAYED를 ▶ 시작 때 지움 | 공연 중 튕김 복귀 때 가장 필요한 표시가 사라짐 |

| 모든 설정 저장 버튼 | 결과가 보이는 항목은 바로 적용이 편함. 트림만 결과가 안 보여 실수 알기 어려움 |
